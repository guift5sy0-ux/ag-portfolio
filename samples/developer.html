QUEST 01팀 4명 · 프론트엔드 담당 · 3개월

캠퍼스 중고거래 웹앱

학과 단위로 거래를 묶는 중고거래 서비스. 검색과 채팅 화면을 만들었습니다.

보상: 베타 사용자 피드백을 받아 화면 두 번 개편

퀘스트 상세 보기

배경과 문제

기존 중고거래 앱에서는 같은 학교 학생을 찾기 어렵고, 거래 장소를 정하는 대화가 길어진다는 불편이 있었습니다.

내 역할

팀원 4명 중 프론트엔드 전담. 검색, 상품 목록, 1:1 채팅 화면을 만들고 백엔드 담당과 API 형식을 맞췄습니다.

과정과 결정

  • 검색 결과가 늦게 뜨는 문제를 줄이려고 입력이 멈춘 뒤 0.3초 후에 요청하도록 바꿨습니다
  • 채팅 화면은 처음엔 새로고침 방식이었지만, 대화가 끊긴다는 피드백을 받고 실시간 방식으로 바꿨습니다
  • 학과 필터를 첫 화면 맨 위로 올려 같은 학과 매물을 먼저 보이게 했습니다

어려웠던 점

실시간 채팅으로 바꾸면서 메시지가 두 번 보이는 문제가 생겼습니다. 메시지마다 고유 번호를 붙여 중복을 걸러 해결했습니다.

결과

베타 테스트 참가자 피드백을 바탕으로 화면을 두 차례 개편했습니다.

배운 점

기능을 다 만든 뒤가 아니라 중간중간 사용자에게 보여줘야 방향을 덜 잃는다는 것을 배웠습니다.

QUEST 02개인 프로젝트 · 1개월

스터디 출석 체크 도구

스터디 모임의 출석과 벌금을 자동으로 계산하는 작은 웹 도구.

보상: 실제 스터디 모임에서 한 학기 사용

퀘스트 상세 보기

배경과 문제

스터디장이 매주 엑셀로 출석과 벌금을 계산하느라 30분씩 쓰고 있었습니다.

내 역할

기획, 디자인, 개발을 혼자 맡았습니다.

과정과 결정

  • 스터디원 5명에게 가장 귀찮은 일을 물어보고 '벌금 계산' 하나에만 집중했습니다
  • 로그인 없이 링크만으로 출석 체크가 되도록 단순하게 만들었습니다

어려웠던 점

지각 기준이 모임마다 달라서, 기준 시간을 스터디장이 직접 정할 수 있게 설정 화면을 추가했습니다.

결과

우리 스터디에서 한 학기 동안 실제로 사용했습니다.

배운 점

작은 도구라도 실제로 쓰는 사람이 있으면 고칠 점이 계속 보인다는 것을 알았습니다.

QUEST 03해커톤 · 팀 3명 · 48시간

동네 가게 대기열 알림

48시간 해커톤에서 만든 대기 순서 알림 서비스의 화면 전체를 맡았습니다.

보상: 교내 해커톤 장려상

퀘스트 상세 보기

배경과 문제

인기 있는 동네 식당 앞에서 손님들이 추운 날씨에 줄을 서서 기다리는 모습에서 출발했습니다.

내 역할

손님용 대기 등록 화면과 가게용 관리 화면을 모두 만들었습니다.

과정과 결정

  • 48시간 안에 끝내기 위해 기능을 '등록, 순서 확인, 호출' 세 가지로 줄였습니다
  • 가게 사장님이 바쁜 중에도 누를 수 있게 호출 버튼을 화면 절반 크기로 키웠습니다

어려웠던 점

발표 직전에 휴대폰에서 화면이 깨지는 문제를 발견해, 가장 작은 화면부터 다시 맞췄습니다.

결과

교내 해커톤에서 장려상을 받았습니다.

배운 점

시간이 부족할수록 무엇을 빼야 하는지 먼저 정해야 한다는 것을 배웠습니다.
